# ScamX — AI CyberShield Platform

An India-focused cybersecurity awareness platform with two detection systems:

1. **Heuristic Detection** — rule-based analysis for deepfake media, voice cloning, phishing messages, WhatsApp fraud, and phishing websites
2. **Machine Learning Fraud Detection** — a genuine classical ML model (Logistic Regression + Random Forest) trained on the public Credit Card Fraud Detection dataset

## Important: What This Is

### Heuristic Detection (existing modules)

These modules use **heuristic/rule-based analysis**, not trained ML models:

- **Byte-entropy analysis** for video/image files (deepfake detector)
- **WAV PCM waveform statistics** for audio files (voice analyzer)
- **Keyword and URL pattern matching** for text messages (phishing/WhatsApp analyzers)
- **Pixel statistics and byte-entropy** for screenshots (website detector)

Results are risk indicators, not definitive proof. The live webcam mode is a visual simulation for demonstration purposes only — it is not real-time AI inference.

### Machine Learning Fraud Detection (ML module)

This module uses a **genuine classical ML model** trained on a real public dataset. The fraud probability comes from the model's `predict_proba()`. It is not a heuristic score, not random, and not hardcoded.

**This is an academic prototype.** It does not represent Indian banking transactions and does not guarantee fraud detection. The probability is not a calibrated confidence score.

## Quick Start

### 1. Install dependencies

```bash
pip install -r backend/requirements.txt
```

### 2. Download the dataset

```bash
python backend/ml/download_data.py
```

The dataset (creditcard.csv, ~150 MB) is **not included in the repository**. The download script fetches it from a public mirror and validates the file (column count, row count, HTML detection). If the automatic download fails, it prints manual instructions.

**Authoritative source:** https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud

### 3. Train the model

```bash
python backend/ml/train_model.py
```

This trains Logistic Regression and Random Forest, selects the best model by validation PR-AUC, and evaluates the selected model on the untouched test set. All four artifacts are saved to `backend/ml/model/`.

### 4. Evaluate (optional — prints saved metrics)

```bash
python backend/ml/evaluate_model.py
```

### 5. Start the Flask backend

**Linux/macOS:**
```bash
python backend/main.py
```

**Windows:**
```cmd
python backend\main.py
```

API runs on `http://localhost:8000`. Health check: `http://localhost:8000/api/health`

If the ML model is not trained, the rest of ScamX works normally. The ML endpoints return a clear `MODEL_NOT_TRAINED` error.

### Frontend

Open `frontend/index.html` in a browser, or serve it with any static file server:
```bash
python -m http.server 5500
```
The frontend expects the backend at `http://localhost:8000`.

## ML Methodology

### Data Split

The dataset is split into three stratified partitions:

| Split | Proportion | Purpose |
|-------|-----------|---------|
| Training | 70% | Train both models |
| Validation | 15% | Model selection (PR-AUC) |
| Test | 15% | Final evaluation (untouched until the end) |

Stratification preserves the fraud/legitimate ratio (~0.17% fraud) in each split. `random_state=42` ensures reproducibility.

### Model Selection

1. Train Logistic Regression and Random Forest on the **training** set
2. Evaluate both on the **validation** set
3. Select the model with the highest **PR-AUC** (average_precision_score) on validation
4. Evaluate the selected model **exactly once** on the **untouched test** set

The test set never influences model selection.

### Class Imbalance

The dataset is highly imbalanced (~0.17% fraud). Both models use `class_weight="balanced"` so the minority class is weighted inversely proportional to its frequency. SMOTE is not used.

### Metrics Explained

Because fraud data is highly imbalanced, **accuracy is misleading** — a model that predicts "always legitimate" would be 99.83% accurate but useless. These metrics are more useful:

- **Precision**: Of all transactions flagged as fraud, what fraction were actually fraud?
- **Recall**: Of all actual fraud transactions, what fraction did the model catch?
- **F1-Score**: Harmonic mean of Precision and Recall
- **PR-AUC**: Area under the Precision-Recall curve — especially informative for imbalanced data
- **Confusion Matrix**: TN / FP / FN / TP

## Dataset

- **Name**: Credit Card Fraud Detection
- **Source**: https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud
- **Records**: 284,807 transactions
- **Fraud cases**: 492 (0.1727%)
- **Legitimate cases**: 284,315
- **Target column**: `Class` (0 = legitimate, 1 = fraud)
- **Features**: 30 — V1 through V28 (PCA-anonymized), Time (seconds since first transaction), Amount
- **Anonymized**: Yes — V1–V28 are PCA principal components; original feature names are not available
- **Missing values**: None
- **Not included in Git**: The dataset (~150 MB) must be downloaded via `python backend/ml/download_data.py`

### Limitations

- **European cardholders** from September 2013 — does **not** represent Indian transactions
- The model is **not** an Indian banking fraud detector
- Highly imbalanced (0.17% fraud)
- Anonymized PCA features limit interpretability
- Does **not** guarantee fraud detection
- The probability from `predict_proba()` is **not** a calibrated confidence score

## Features

### Heuristic Detection
- **Deepfake Detector**: Upload video/image, byte-entropy heuristic scoring
- **Voice Scam Analyzer**: Upload audio, WAV PCM waveform statistics or byte-entropy fallback
- **Phishing Analyzer**: Paste suspicious SMS/email, keyword + URL pattern matching
- **WhatsApp Scam Analyzer**: Paste WhatsApp message, India-specific fraud patterns
- **Website Detector**: Upload screenshot, pixel analysis + byte-entropy heuristics
- **Cybersecurity Assistant**: Rule-based Q&A with India emergency contacts
- **Threat Dashboard**: Session security score, detection breakdown, baseline predictions
- **Detection History**: Combined session + SQLite database records
- **India Threat Map**: SVG map with city markers, state heatmap, hotspots
- **Live Detection**: Webcam preview with simulated risk scoring (demo/simulation mode)

### Machine Learning Fraud Detection
- Enter transaction features (V1–V28, Time, Amount), get real fraud probability from the trained model
- Model comparison: validation metrics for Logistic Regression vs Random Forest
- Evaluation dashboard: Precision, Recall, F1, PR-AUC, Confusion Matrix — all from actual model evaluation on the untouched test set

## Data Persistence

- **Detections**: SQLite (`backend/cybershield.db`) with WAL mode. Auto-creates on first run.
- **ML Predictions**: Separate `ml_predictions` table (prediction, fraud_probability, model_name, timestamp). No sensitive payment data is stored.
- Existing detection data is preserved when the ML table is added (`CREATE TABLE IF NOT EXISTS`).

## Security Notes

- CORS restricted to configurable allowed origins
- `MAX_CONTENT_LENGTH` enforced (200MB video, 100MB audio, 20MB image)
- File signature validation (RIFF/WAVE for WAV, ISO BMFF ftyp for M4A/MP4, magic bytes for other formats)
- `secure_filename` on all uploaded files
- All user-generated content HTML-escaped in the frontend
- Input validation on all API endpoints (city, detection type, pagination, ML features)
- Consistent error responses with structured error codes
- ML model only loads project-generated joblib files — never user-uploaded model files
- No `eval()`, `exec()`, `pickle.load()` on untrusted input, or subprocess execution
- Parameterized SQL throughout
- Environment-controlled debug mode (OFF by default)
- Camera allowed via `Permissions-Policy: camera=(self)` for Live Detection; microphone and geolocation disabled
- ML prediction endpoint rejects NaN, Infinity, and non-numeric input
- If DB storage of an ML prediction fails, the API returns `stored: false` rather than silently claiming success
